AI Gym

Ocho retos progresivos para convertir la teoría en músculo. Cada uno se asigna en una sesión, se trabaja durante la semana y se revisa en la siguiente.

Reglas del gimnasio

Criterios medibles

Cada reto tiene criterios de aceptación medibles. Nada de «más o menos funciona»: hay un golden set, una métrica o un comportamiento verificable que define el éxito.

Definición de «done»

Un reto está terminado cuando los criterios de aceptación se cumplen y el resultado se revisó en sesión. Sin revisión, no cuenta.

Política de pistas

Cada reto trae pistas escalonadas. Antes de abrir cada una, intenta resolver el bloqueo por tu cuenta al menos 30 minutos. La fricción es parte del entrenamiento.

Todo vive en tu repo

Cada reto vive en el repo del alumno: código, README, evidencia de las métricas y commits con historia real. Al final del programa, ese repo es tu portfolio.

Katas de nivelación: Pre-Fase 0.5

Ocho katas de fundamentos de Python (kata-00 a kata-07), cada una entrena un fundamento distinto sobre su propio dominio pequeño (entorno, conversores, texto, contactos, CSV→JSON, errores, una clase) y cierran con un capstone a elección. Cada una trae harness pytest con datos golden inline: se consideran done con pytest -q en verde. Bloque condicional: solo se activan si el diagnóstico indica nivelación.

Los retos

01
Fase 1 Se asigna en la sesión 2

Extractor estructurado

Extraer datos estructurados (JSON validado con Pydantic) de 20 textos libres (p. ej. ofertas de trabajo o emails de soporte) usando solo prompting. Se evalúa contra un golden set: exactitud por campo ≥ 90%. Sin tool use todavía: el punto es prompting disciplinado + validación.

Ver enunciado →
02
Fase 1 Se asigna en la sesión 3

Tool use robusto

Asistente con 3 herramientas via function calling (p. ej. clima, conversión de moneda, búsqueda en una "DB" local). Las tools fallan a propósito (timeouts, 500s, JSON malformado) mediante un harness de caos provisto en el enunciado. El asistente debe sobrevivir: retries con backoff exponencial, mensajes de error útiles al usuario, nunca crashear. Se evalúa corriendo 20 conversaciones con fallos inyectados.

Ver enunciado →
03
Fase 2 Se asigna en la sesión 4

RAG básico con citas

Pipeline RAG completo sobre documentación técnica real que el alumno elija (p. ej. docs de FastAPI o de la API de Anthropic): ingesta, chunking justificado, embeddings, vector store local, retrieval top-k, generación con citas a la fuente. Se evalúa con 15 preguntas de prueba: la respuesta debe ser correcta Y citar el documento correcto.

Ver enunciado →
04
Fase 2 Se asigna en la sesión 5

Tuning de retrieval con métricas

Construir un golden set de retrieval (25+ pares pregunta→chunks relevantes) para el RAG del reto 3. Medir recall@5 y MRR como baseline. Implementar búsqueda híbrida (BM25 + vectores con RRF) y reranking. Entregable: tabla comparativa baseline vs mejorado con las métricas. La mejora debe ser real y explicada.

Ver enunciado →
05
Fase 2 Se asigna en la sesión 6

Agente desde cero

Agente investigador SIN frameworks (solo el SDK del modelo): loop LLM → decide tool → ejecuta → observa → repite, con presupuesto máximo de pasos y tokens. Tools: búsqueda web o lectura de archivos locales. Produce un informe markdown con fuentes citadas. Se evalúa: el loop es legible (<200 líneas), respeta presupuestos, el informe responde la pregunta.

06
Fase 2 Se asigna en la sesión 7

Agente con memoria

Extender el agente del reto 5 con: (a) memoria persistente entre ejecuciones (archivos o SQLite) que recuerda hallazgos previos, y (b) un subagente especializado al que delega una subtarea. Demostrar con un caso: segunda ejecución sobre el mismo tema reutiliza memoria y es más rápida/barata. Bonus: exponer las tools como MCP server.

07
Fase 2 Se asigna en la sesión 8

Suite de evals

Suite de 30+ casos de eval para el RAG (reto 3-4) o el agente (reto 5-6): mezcla de asserts programáticos y LLM-as-judge con rúbrica explícita. Integrada a CI (GitHub Actions): corre en cada PR y reporta score. Entregable: score baseline documentado + un cambio que mejora el score, con evidencia. Esta es la pieza más valiosa del portfolio.

08
Fase 3 Se asigna en la sesión 10

Hardening de producción

Tomar el mejor proyecto y endurecerlo en dos partes. Parte 1 (semana 10): instrumentar trazas, tokens, costo y latencia; dashboard simple; reducir p95 o costo 30% (caching, routing de modelos, prompts más cortos) y documentar el antes/después. Parte 2 (semana 11): red-team propio con 10 ataques de prompt injection documentados + 3 mitigaciones implementadas y demostradas con los ataques bloqueados.
