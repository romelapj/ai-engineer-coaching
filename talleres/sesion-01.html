Taller 01 · Tokens, dinero y vectores: lo que hay debajo del modelo

El modelo no lee letras, lee tokens. Y esos tokens son tu factura. En 5 días de 30 minutos, más el día 0 de preparación, construyes el Token-ó-metro, ves los parámetros de muestreo trabajando, y tocas los vectores que sostienen todo lo que viene.

Un día = 30 minutos = un archivo que corre. No leas el taller entero de corrido: haz un día, ciérralo, y vuelve mañana. Cada paso trae el código completo (botón Copiar), el comando para correrlo y la salida real que deberías ver: esa salida es tu criterio de "me funcionó", sin tener que preguntarle a nadie.

Este es el taller más barato del curso: casi todo usa count_tokens, que es gratis. Solo los días 3 y 4 gastan unos centavos.

Marca cada paso con el círculo de la izquierda: tu progreso queda guardado en este navegador. Atajos: j / k para saltar entre pasos, w para ajustar líneas, c para las notas del coach.

La historia de esta sesión

Sabes usar un modelo: le escribes, te responde. Esta sesión va de lo que pasa antes de que te responda, y de lo que aparece después en la factura.

Hay tres cosas que casi nadie mira hasta que le duelen. Que el modelo no lee letras, lee tokens, y por eso no sabe contar las erres de "strawberry". Que esos tokens son literalmente dinero, y que puedes contarlos antes de gastar. Y que hay una respuesta cortada a media frase esperándote en producción sin lanzar ningún error.

El modelo no ve letras: ve tokens

Antes de llegar al modelo, tu texto se parte en pedazos llamados tokens. Esa unidad explica dos cosas a la vez: por qué se equivoca contando las erres de "strawberry", y cuánto vas a pagar.

def contar(texto):    # count_tokens NO genera respuesta ni consume tokens de salida: solo    # cuenta. Por qué

El conteo es específico del modelo: cada familia tokeniza distinto, así que el mismo texto puede dar números diferentes. Por eso model es obligatorio aquí y no un detalle.

Por qué

El español rinde 3.26 caracteres por token; el JSON, 1.98. Las llaves, las comillas y las sangrías son tokens que pagas igual que las palabras. Ese dato debería cambiar cómo diseñas tus prompts: pedir JSON tiene un costo, y a veces no compensa. Y abajo, strawberry: 9 tokens para 10 caracteres. El modelo no ve las tres erres porque no ve letras: ve un puñado de números que representan pedazos de palabra. Todos los fallos de "cuenta las letras de esta palabra" salen de ahí, y ninguno se arregla con un prompt mejor.

3.3

Contar y multiplicar

6 min

Dos funciones cortas: una cuenta, la otra convierte tokens en dólares.

01_tokenometro.py · líneas 45–63+19 líneas nuevas
def contar_entrada(texto, modelo):    # El conteo es específico del modelo: el mismo texto puede dar números    # distintos en modelos distintos, así que se cuenta con cada uno.    resp = client.messages.count_tokens(        model=modelo,        messages=[{"role": "user", "content": texto}],    )    return resp.input_tokensdef costo(tokens_entrada, tokens_salida, precio_entrada, precio_salida):    # Los precios vienen por millón de tokens: dividimos entre 1.000.000    # para obtener el costo de UNA petición.    return (        tokens_entrada * precio_entrada / 1_000_000        + tokens_salida * precio_salida / 1_000_000    )
Por qué

Los precios vienen "por millón de tokens" porque los números por token serían ilegibles. Dividir entre 1.000.000 es todo el misterio, pero es donde se cuelan los errores de tres ceros.

6.2

La similitud coseno, en tres operaciones

9 min

Producto punto dividido entre el producto de las longitudes. Eso es todo.

def coseno(a, b):    # Producto punto: suma de multiplicar los vectores elemento a elemento.    # Es grande cuando los dos apuntan hacia el mismo lado.    punto = sum(x * y for x, y in zip(a, b))    # La "longitud" (norma) de cada vector: la raíz de la suma de cuadrados.    norma_a = math.sqrt(sum(x * x for x in a))    norma_b = math.sqrt(sum(y * y for y in b))    # Dividir entre las longitudes deja solo el ÁNGULO: así una frase larga    # y una corta se pueden comparar de igual a igual.    return punto / (norma_a * norma_b)
Por qué

La división entre las normas es lo que hace útil la fórmula: elimina la magnitud y deja solo el ángulo. Por eso una frase de tres palabras y un párrafo de cien se pueden comparar de igual a igual. 1.0 es la misma dirección, 0.0 es sin relación, y sí, puede salir negativo: direcciones opuestas.

def comparar(idioma, frases):    vectores = embed(frases)    print(f"\n--- {idioma} ---")    print(f'similitud contra "{frases[0]}":\n')    for frase, vector in zip(frases, vectores):        sim = coseno(vectores[0], vector)        # Barra visual para ver la escala de un vistazo. Por qué

La barra no es decoración: los números sueltos se leen mal y las diferencias importantes se pierden entre decimales. Ver la escala hace que el resultado del paso siguiente salte a la vista.
