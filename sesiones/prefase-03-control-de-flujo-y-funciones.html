Control de flujo, a la Pythonic

El for itera sobre el iterable directo, no sobre índices. El while es para "hasta que se cumpla una condición"; casi siempre prefieres for. Y salir temprano con return/break expresa mejor la intención que una bandera booleana. 

def primer_negativo(nums):
    for n in nums:
        if n < 0:
            return n          # salir temprano > bandera + break
    return None

print(primer_negativo([3, 7, -2, 9]))   # -2

# saltar elementos invalidos sin anidar ifs:
for linea in ["ok", "", "dato", "  "]:
    if not linea.strip():
        continue              # ignora vacias
    print(linea)

for-else: el patrón que casi nadie conoce

  • El else de un for/while se ejecuta solo si el loop terminó sin break.
  • Léelo como "no-break": el else corre cuando no encontraste lo que buscabas.
  • Reemplaza la bandera encontrado = False por algo declarativo.
  • Aplica igual al while; úsalo para búsquedas y validaciones. 
def buscar(secuencia, objetivo):
    for x in secuencia:
        if x == objetivo:
            print(f"encontrado: {x}")
            break
    else:
        print("no estaba en la secuencia")

buscar([1, 2, 3], 2)   # encontrado: 2
buscar([1, 2, 3], 9)   # no estaba

Funciones: posicionales, nombrados y defaults

El control de flujo decide qué corre; las funciones deciden si eso queda legible o en un bloque interminable: son las piezas con nombre en las que partirás el monolito de hoy. Los argumentos van por posición o por nombre; los defaults se ponen al final de la firma. Llamar por keyword hace el call-site legible. Un argumento con default es opcional; sin default es obligatorio. Devuelve varios valores como tupla y desempaquétalos. 

def crear_usuario(nombre, rol="lector", activo=True):
    return {"nombre": nombre, "rol": rol, "activo": activo}

print(crear_usuario("Ada"))
print(crear_usuario("Alan", rol="admin"))   # keyword: legible

def dividir(a, b):
    return a // b, a % b        # devuelve una tupla

cociente, resto = dividir(17, 5)   # desempaquetado
print(cociente, resto)             # 3 2

*args y **kwargs: aridad variable

*args recoge posicionales extra como tupla; **kwargs recoge nombrados extra como dict. En la llamada, * desempaqueta una lista en posicionales y ** un dict en nombrados. Ideal para wrappers que reenvían argumentos sin conocerlos. Orden de firma: posicionales, *args, keyword-only, **kwargs. 

def suma(*numeros):
    return sum(numeros)
print(suma(1, 2, 3, 4))          # 10

def configurar(**opciones):
    for k, v in opciones.items():
        print(f"{k} = {v}")
configurar(debug=True, nivel=3)

valores = [1, 2, 3]
print(suma(*valores))            # desempaqueta la lista -> 6

El bug del default mutable

Los defaults se evalúan una sola vez, cuando se define la función — no en cada llamada. Por eso def f(items=[]) comparte la misma lista entre todas las llamadas: se acumula basura.

El patrón correcto es default None y crear la colección dentro. Es uno de los gotchas más preguntados en entrevistas — y un bug real en producción.

Default mutable: el patrón correcto

# MAL: la lista se comparte entre llamadas
def agregar_malo(item, bolsa=[]):
    bolsa.append(item)
    return bolsa
print(agregar_malo("a"))   # ['a']
print(agregar_malo("b"))   # ['a', 'b']  <- fuga!

# BIEN:
def agregar(item, bolsa=None):
    if bolsa is None:
        bolsa = []
    bolsa.append(item)
    return bolsa
print(agregar("a"))   # ['a']
print(agregar("b"))   # ['b']  <- aislado

Scope: la regla LEGB

  • Python resuelve nombres en este orden: Local → Enclosing → Global → Built-in.
  • No declaras variables: asignar dentro de una función crea un nombre local.
  • Para reasignar una global desde dentro necesitas global; para una enclosing, nonlocal (ambos raros).
  • Leer una variable de fuera sí funciona sin nada; el problema es solo al reasignar.
  • Built-in es el último escalón: len, print, range — no los pises (no llames list a una lista). 
x = "global"

def externa():
    x = "enclosing"
    def interna():
        x = "local"      # crea LOCAL nuevo
        print(x)
    interna()             # local
    print(x)                 # enclosing

externa()
print(x)                     # global

Funciones como objetos de primera clase

Una función es un objeto: la asignas, la pasas como argumento, la devuelves. sorted(key=...), map() y filter() reciben una función. Es la base de los callbacks y, más adelante, de los decoradores. lambda es una función anónima de una expresión: úsala para keys cortas, no para lógica compleja. 

def aplicar(func, datos):
    return [func(x) for x in datos]

print(aplicar(str.upper, ["a", "b"]))   # ['A', 'B']

productos = [("taza", 5), ("libro", 12), ("pin", 2)]
por_precio = sorted(productos, key=lambda p: p[1])
print(por_precio[0])        # ('pin', 2)

import operator
por_precio2 = sorted(productos, key=operator.itemgetter(1))  # sin lambda

Type hints: documentación que se lee (y verifica mypy)

Las anotaciones documentan tipos en la firma: no cambian el comportamiento en runtime. Python no valida, pero tú, tu IDE y mypy sí. Las que más usarás: list[int], dict[str, float], str | None (opcional). Hacen el código autoexplicativo y atrapan bugs antes de correr, con una herramienta aparte. 

def promedio(valores: list[float]) -> float:
    return sum(valores) / len(valores)

def buscar_precio(catalogo: dict[str, float], nombre: str) -> float | None:
    return catalogo.get(nombre)   # None si no esta

# Python NO obliga el tipo en runtime:
print(promedio([1, 2, 3]))      # 2.0  (ints pasan, el hint no falla)
# pero `mypy archivo.py` avisaria de un mal uso antes de correr
