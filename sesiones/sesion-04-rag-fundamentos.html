RAG vs fine-tuning vs long context

Enfoque Úsalo cuando Costo real Citas
RAG El conocimiento cambia seguido y necesitas trazabilidad Embeddings (~$0.02–0.13 / M tokens) + vector store; actualizar un doc toma minutos Sí, nativas
Fine-tuning Quieres cambiar estilo o formato, no inyectar conocimiento Dataset curado + entrenamiento; re-entrenas con cada cambio de contenido No
Long context Corpus pequeño y estable (cabe en ~200K tokens) Pagas el corpus entero en cada query (150K tokens/pregunta vs ~2K con RAG); prompt caching (reusar el prefijo repetido del prompt entre llamadas, con descuento — lo verás en la sesión 09) lo mitiga, no lo elimina Parciales

Regla práctica: si la pregunta es "¿cómo le doy conocimiento de mis docs al modelo?", la respuesta casi siempre empieza por RAG. Fine-tuning para conocimiento es el error de novato más caro.

El pipeline RAG en una línea

Ingesta → Chunking → Embeddings → Vector store → Retrieval (top-k) → Generación con citas

El modelo no puede citar lo que tu retrieval no encontró. La calidad de un RAG se decide antes de llamar al LLM.
  • Indexación (offline): partes los documentos, los conviertes en vectores y los guardas. Se paga una vez por documento.
  • Consulta (online): conviertes la pregunta en vector, recuperas los k chunks más cercanos y se los pasas al modelo con instrucciones de citar. Se paga en cada query.
  • El 80% de los bugs de RAG en producción están en indexación: chunks mal cortados, metadata perdida, modelo de embeddings inconsistente.

Ese es el mapa de hoy: de aquí en adelante recorremos cada caja del diagrama, una por una — arrancando por el chunking.

Chunking: tres estrategias, un criterio

📏

Tamaño fijo

  • 512–1024 tokens, overlap 10–15%
  • Trivial de implementar, tu baseline
  • Corta frases y secciones por la mitad
  • Úsalo para validar el pipeline, no para producción
🧠

Semántico

  • Corta donde la similitud entre frases consecutivas cae
  • Chunks coherentes por tema
  • Cuesta embeddings extra en la ingesta
  • Brilla en prosa sin estructura (transcripts, emails)
🏗️

Por estructura

  • Headers de Markdown, secciones HTML, funciones en código
  • Respeta los límites que el autor ya definió
  • Guarda metadata: título, sección, URL
  • La mejor opción para documentación técnica — el reto

Criterio: un chunk debe responder una pregunta por sí solo. Si al leerlo aislado no se entiende, tu retrieval va a devolver ruido.

Chunking por estructura, en 20 líneas

# Markdown técnico: cada sección H2/H3 es un chunk con metadata.
import re

def split_max_tokens(texto: str, max_tokens=800, overlap=100) -> list[str]:
    # Aproxima tokens por palabras (~1 palabra ≈ 1.3 tokens) y corta con solape.
    palabras = texto.split()
    tam = int(max_tokens / 1.3)
    paso = max(1, tam - int(overlap / 1.3))
    return [" ".join(palabras[i : i + tam]) for i in range(0, len(palabras), paso)] or [texto]

def chunk_markdown(texto: str, fuente: str) -> list[dict]:
    # (?=...) = lookahead: re.split corta ANTES de cada '## '/'### ' sin borrar el header del chunk.
    secciones = re.split(r"\n(?=#{2,3} )", texto)
    chunks = []
    for sec in secciones:
        titulo = sec.splitlines()[0].lstrip("# ")
        # Secciones gigantes: sub-divide a ~800 tokens con overlap.
        for parte in split_max_tokens(sec, max_tokens=800, overlap=100):
            chunks.append({
                "texto": parte,
                "fuente": fuente,
                "seccion": titulo,
            })
    return chunks

La metadata (fuente, seccion) no es decoración: es lo que convierte una respuesta en una respuesta citable.

Embeddings: los trade-offs que importan

Modelo Dim Costo aprox. Cuándo
voyage-3.5-lite (Voyage AI) 1024 ~$0.02 / M tokens Default económico; es el proveedor que recomienda Anthropic
text-embedding-3-small (OpenAI) 1536 ~$0.02 / M tokens Si ya vives en ese ecosistema
text-embedding-3-large (OpenAI) 3072 ~$0.13 / M tokens Máxima calidad managed; 2× storage que small
bge-m3 / MiniLM (open source) 1024 / 384 Gratis, corre local Datos sensibles, prototipos sin API key
  • Más dimensiones = mejor calidad pero más storage: 1536 dims en float32 ≈ 6 KB/vector → 1M de chunks ≈ 6 GB de índice.
  • Regla de oro: el mismo modelo para indexar y para consultar. Mezclarlos rompe el retrieval en silencio.

Vector stores: pgvector, Chroma, Qdrant

🐘

pgvector

  • Extensión de Postgres — cero infra nueva
  • Vectores junto a tus datos transaccionales, con SQL y joins
  • Índice HNSW; cómodo hasta unos pocos millones de vectores
  • Default en producción si ya usas Postgres
🧪

Chroma

  • Embebido en tu proceso Python, persiste a disco
  • De pip install a query en 5 minutos
  • No pensado para alta concurrencia ni escala grande
  • Ideal para prototipos — y para el reto 03
🚀

Qdrant

  • Motor dedicado (Rust), API REST/gRPC
  • Filtros por payload + búsqueda vectorial en una sola query
  • Quantization para escalar a decenas de millones
  • Cuando el retrieval ES el producto

No empieces eligiendo base de datos. Empieza con Chroma, mide, y migra cuando los números te lo pidan — la interfaz es la misma idea en todos: upsert de vectores + query por similitud.

Top-k retrieval y umbrales de similitud

  • k = 3–5 es el punto de partida sano. Más k = más tokens, más latencia y más ruido que confunde al modelo.
  • Umbral de similitud: si el mejor chunk queda por debajo, la respuesta correcta es "no tengo evidencia" — no inventar.
  • El umbral depende del modelo de embeddings y de tu corpus: calíbralo con 10–20 preguntas reales, no lo copies de un blog.
  • Síntoma clásico: respuestas "plausibles pero falsas" = el retrieval devolvió chunks irrelevantes y el modelo rellenó. 
# pip install chromadb
import chromadb
import anthropic

chroma = chromadb.PersistentClient("./rag_db")
collection = chroma.get_or_create_collection("docs")
client = anthropic.Anthropic()  # el mismo cliente para todo el archivo
UMBRAL = 0.7  # punto de partida; calíbralo con tus 10-20 preguntas reales.

def responder(pregunta: str) -> str:
    results = collection.query(
        query_texts=[pregunta],
        n_results=4,
    )
    # [0] = la 1ª (y única) query del batch: Chroma devuelve una lista por query_text.
    # Chroma devuelve distancia coseno: similitud = 1 - distancia
    hits = [
        {**meta, "texto": doc}
        for doc, meta, dist in zip(
            results["documents"][0],
            results["metadatas"][0],
            results["distances"][0],
        )
        if 1 - dist >= UMBRAL  # calibrado, no adivinado
    ]
    if not hits:
        return "No tengo evidencia para responder."
    # ...la generación con citas continúa en la slide 11, dentro de responder().

Generación con citas obligatorias

    # ...seguimos dentro de responder(pregunta), ya con los hits del retrieval:
    SYSTEM = (
        "Responde SOLO con el contexto provisto. "
        "Cita cada afirmación con su marcador [n]. "
        "Si el contexto no alcanza, responde exactamente: "
        "'No tengo evidencia para responder.'"
    )

    contexto = "\n\n".join(
        f"[{i + 1}] ({c['fuente']} § {c['seccion']})\n{c['texto']}"
        for i, c in enumerate(hits)
    )

    resp = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=1024,
        system=SYSTEM,
        messages=[{
            "role": "user",
            "content": f"Contexto:\n{contexto}\n\nPregunta: {pregunta}",
        }],
    )
    return resp.content[0].text  # "...el timeout default es 30s [2]."

🛠️ Manos al código — 30 min juntos

Construimos un mini-RAG sobre la documentación en Markdown de este mismo programa de coaching, en un solo archivo Python:

  • Min 0–8: ingesta + chunking por headers de Markdown con metadata (fuente, seccion) — la función de la slide 7.
  • Min 8–15: embeddings e indexación en Chroma persistente (chromadb.PersistentClient).
  • Min 15–22: loop de consulta: top-4, umbral de similitud, y el caso "sin evidencia".
  • Min 22–30: generación con claude-sonnet-4-6 y citas [n]; probamos 3 preguntas — una respondible, una ambigua y una que NO está en los docs.

Meta del bloque: que la pregunta trampa devuelva "No tengo evidencia para responder" en vez de una alucinación elegante.
