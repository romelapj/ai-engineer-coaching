Por qué estás aquí

"AI engineer" es el puesto que todos piden y nadie define

En 2026 las vacantes lo gritan por todos lados, pero cada una describe algo distinto. Detrás del ruido hay un rol con un núcleo concreto y evaluable: construir producto fiable sobre los mejores modelos del mundo, sin entrenar ninguno.

En los próximos 90 minutos vas a saber exactamente qué evalúan las entrevistas de este rol, y vas a dejar tu primera llamada a Claude corriendo en tu máquina.

AI engineer vs ML engineer vs data scientist

Rol Pregunta que responde Entregable típico Stack núcleo
Data scientist ¿Qué dicen los datos y qué decisión soportan? Análisis, dashboards, modelos estadísticos SQL, pandas, scikit-learn, notebooks
ML engineer ¿Cómo entreno y sirvo modelos propios a escala? Pipelines de training y serving PyTorch, feature stores, MLOps, GPUs
AI engineer ¿Cómo construyo producto fiable sobre modelos frontera? Features con LLM en producción APIs de LLM, RAG, agentes, evals

La diferencia clave: el AI engineer no entrena modelos. Consume modelos frontera vía API y resuelve el problema difícil que queda: hacerlos fiables, medibles y rentables en producción.

Ese "hacerlo fiable en producción" no es una sola cosa: se reparte en áreas concretas, y son exactamente las que evalúan las entrevistas.

Qué evalúan las entrevistas en 2026

🔌

Integración LLM

Streaming, tool use, structured output, reintentos ante rate limits. Lo mínimo para no quedar fuera en la primera ronda.

📚

RAG

Chunking, embeddings, retrieval híbrido, citar fuentes. Y saber decir cuándo no usar RAG.

🤖

Agentes

Loop de tools, planificación, límites de pasos y presupuesto. Diseñar el agente más simple que resuelve el problema.

🧪

Evals

Datasets dorados, LLM-as-judge, regresión de prompts. Es lo que separa a un junior de un senior en este rol.

🏭

Producción

Latencia, costo por request, caching, fallbacks, observabilidad. "Funciona en el demo" no es el estándar.

🗣️

Diseño oral

Defender trade-offs en voz alta: ¿por qué RAG y no fine-tuning? ¿Por qué un workflow y no un agente?

Basta de teoría: abramos la terminal. En los próximos 30 minutos dejas el entorno listo y escribes ask.py, tu primer script.

Setup del entorno

# 1. Python 3.11+ y un entorno virtual
python3 --version
python3 -m venv .venv
source .venv/bin/activate

# 2. SDK oficial de Anthropic
pip install anthropic

# 3. API key (console.anthropic.com → API Keys)
export ANTHROPIC_API_KEY="sk-ant-..."

# Regla de higiene: la key vive en variables de entorno,
# NUNCA hardcodeada ni commiteada al repo.

El SDK lee ANTHROPIC_API_KEY del entorno automáticamente: cero configuración extra en el código.

Tu primera llamada a Claude

# hello_claude.py
import anthropic

client = anthropic.Anthropic()  # lee ANTHROPIC_API_KEY del entorno

resp = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "Explica en 2 líneas qué hace un AI engineer."}
    ],
)

print(resp.content[0].text)  # content es una LISTA de bloques; [0].text = el texto del primero (anatomía completa en Sesión 02)
print(f"tokens → in: {resp.usage.input_tokens}, out: {resp.usage.output_tokens}")

Fíjate en resp.usage: desde el día 1 medimos tokens, porque tokens = latencia y costo. Ese hábito te acompaña todo el programa.

🛠️ Manos al código: 30 min en pair

Construimos juntos ask.py: un mini CLI que pregunta a Claude desde la terminal.

Qué debe hacer

  • Recibir la pregunta como argumento: python ask.py "tu pregunta"
  • Llamar a claude-sonnet-4-6 con el SDK
  • Imprimir la respuesta + tokens de entrada y salida
import sys

pregunta = sys.argv[1]  # argumentos de la terminal; [0] es el nombre del script
sys.exit(1)             # exit code ≠ 0 = terminó con error (0 = todo bien)

Casos que debe sobrevivir

  • Sin ANTHROPIC_API_KEY → mensaje claro, exit code 1
  • Sin argumento → muestra cómo usarlo
  • Error de API (anthropic.APIError) → captura y reporta, sin traceback crudo

Tú escribes, yo navego. Este script es la semilla del assessment y del reto de la semana.

Parte 3
