De tu lenguaje a Python: el mapa rápido

Lo que ya sabes

  • Variables, if, for, while y funciones son universales: iremos rápido ahí.
  • Sin new, sin punto y coma, sin compilar a binario: editas y corres.

Lo que es nuevo (lo denso)

  • Lo Pythonic: truthiness, mutabilidad, comprehensions, generadores, dunder, EAFP.
  • Sin llaves: la indentación ES la sintaxis de bloque (4 espacios, nunca tabs).
  • Tipado dinámico pero no débil: Python no convierte '3' + 4 por ti.

Cómo se ejecuta tu código

El intérprete

  • CPython lee tu .py, lo compila a bytecode (.pyc) y lo ejecuta en una máquina virtual.
  • No hay paso de "compilar a ejecutable" como en Go o Java: python script.py corre directo.
  • Los errores de sintaxis se ven al cargar; los de ejecución saltan al llegar a la línea.

El REPL

  • python sin argumentos evalúa expresiones una a una: tu laboratorio interactivo.
  • python -i script.py corre el script y te deja dentro, con todas las variables vivas para inspeccionar.

Todo es un objeto

Un int, una función, una clase, un módulo: en Python TODO es un objeto con identidad, tipo y valor. Un nombre no "contiene" un valor — es una etiqueta que apunta a un objeto en memoria.

Con type(x) ves la clase, con id(x) la identidad y con dir(x) qué sabe hacer. Esto explica casi todo lo raro de Python: por qué dos listas "iguales" no son "la misma", o por qué pasar una lista a una función puede mutarla.

Nombres, objetos y el REPL como microscopio

>>> precio = 1990          # 'precio' apunta a un objeto int
>>> type(precio)
<class 'int'>
>>> texto = "1990"
>>> type(texto), repr(texto)
(<class 'str'>, "'1990'")
>>> precio == texto         # int vs str: nunca iguales
False
>>> dir(texto)[-5:]         # explorar qué sabe hacer un str
['swapcase', 'title', 'translate', 'upper', 'zfill']

No escribas 40 líneas y reces: carga un dato y míralo. repr('500') muestra comillas y distingue el str del int.

Tipado dinámico, pero fuerte

Dinámico

  • Una variable puede apuntar a un int hoy y a un str después; no declaras el tipo en la firma.

Fuerte

  • Python no mezcla tipos a la fuerza: '3' + 4 lanza TypeError, no devuelve '34' ni 7.
  • Compáralo con JS, donde '3' + 4 === '34': Python prefiere fallar ruidoso a adivinar. 
# Conversión SIEMPRE explícita
int("3") + 4        # 7
str(4) + "3"        # '43'

"3" + 4              # TypeError

Es una virtud: el error salta donde está el bug, no tres funciones después.

None y la verdad sobre la ausencia

def saludar(nombre):
    print(f"Hola, {nombre}")
    # sin return explícito

resultado = saludar("Ada")
print(resultado)            # None
print(resultado is None)    # True  <- la forma idiomática

config = {"timeout": 30}
valor = config.get("reintentos")   # clave ausente -> None, no error
print(valor is None)        # True

None es el objeto singleton que representa "ausencia de valor" (como null/nil, pero es un objeto). Se compara con is None, no con == None — el porqué lo vemos en N01: identidad vs igualdad.

Indentación: la sintaxis del bloque

  • En Python la indentación NO es estética: define qué pertenece a cada bloque.
  • 4 espacios por nivel, consistentes; mezclar tabs y espacios lanza TabError.
  • No hay llaves ni end: el bloque empieza tras los dos puntos y termina cuando baja la indentación.
  • Un IndentationError casi siempre es un espacio de más o de menos, o un tab colado.
  • Configura tu editor: "insertar espacios al pulsar Tab" y 4 espacios.

Anatomía de un traceback

Aquí el modelo mental deja de ser teoría: si sabes qué es un objeto, un tipo y un nombre, un traceback deja de ser ruido que asusta y pasa a ser un mensaje preciso — nombra el tipo del error y el objeto exacto que lo provocó.

  • Se lee de abajo hacia arriba: la última línea es el tipo y el mensaje del error.
  • La sección de arriba es la pila de llamadas; busca el frame de tu código.
  • La penúltima sección dice archivo y número de línea exacto donde explotó.
  • ValueError: invalid literal for int() with base 10: 'abc' significa que hiciste int('abc').
  • La causa raíz casi nunca es la línea del error: suele ser el dato que llegó sucio.

Los 5 tracebacks que más vas a ver

Excepción Ejemplo típico Qué la causa / cómo evitarla
ValueError int('abc'), float malformado El dato venía sucio: convierte con cuidado.
KeyError d['nope'] en un dict normal Usa d.get(k, default) o defaultdict.
TypeError 'x' + 3, None + int Conversión de tipos olvidada.
IndexError lista[5] con 3 elementos Valida len() antes de indexar.
FileNotFoundError open() con ruta mala Usa pathlib y verifica .exists().

Leyendo un traceback de verdad

# Lee de ABAJO hacia ARRIBA
Traceback (most recent call last):
  File "agenda.py", line 12, in <module>
    edad = int(fila["edad"])
ValueError: invalid literal for int() with base 10: ''

# tipo=ValueError | archivo=agenda.py | línea=12 | causa=int('')
# Causa raíz: una fila de la agenda venía con 'edad' vacía
# Reproducción mínima en el REPL:  int('')  -> reproduce el bug

Patrón: lee el mensaje, ve a la línea, reproduce el error en una línea en el REPL. Anti-patrón: cambiar código al azar hasta que "deje de fallar". El error te dice qué pasó; tu trabajo es entender por qué llegó ese dato.

El ritual de entorno, de memoria

# Esto tiene que salirte sin pensar
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
pip install pytest
pip freeze > requirements.txt

# Verifica SIEMPRE antes de seguir:
python -c "import sys; print(sys.version)"
which python                       # debe apuntar dentro de .venv

venv aísla dependencias por proyecto y mata el "funciona en mi máquina"; requirements.txt es tu contrato de reproducibilidad. Tenlo a mano: es el primer paso del montaje.

Manos al código — Entorno + cazar 3 tracebacks (35 min)

  • 1) Montar (10 min): carpeta nivelacion-python/, crear venv, instalar pytest, pip freeze y verificar con un import.
  • 2) Mirar antes de codear (5 min): abre un dataset chico en el REPL y di qué tipo es cada campo.
  • 3) Cazar 3 tracebacks (15 min): recibes 3 scripts rotos (ValueError, KeyError, IndexError); para cada uno di tipo/línea/causa en voz alta, reprodúcelo en el REPL y arréglalo.
  • 4) Inspeccionar estado (5 min): corre python -i sobre el script arreglado y explora las variables vivas.

Kata del día — kata-00

Kata kata-00 Entregable

Smoke test de entorno

Un repo con venv, requirements.txt y un test_smoke.py que verifique que importas pytest, que la versión de Python es 3.10+ y que una función propia trivial devuelve lo esperado.

Criterio medible: pytest pasa 3/3 en verde y el python -c del import no falla. De-riskea el "no me corrió nada" antes de que importe en katas con datos reales.

Checklist de salida

  • Creo y activo un venv, instalo paquetes y genero requirements.txt sin googlear.
  • Uso el REPL y python -i para inspeccionar tipos y valores antes de escribir el script completo.
  • Explico "todo es objeto" y por qué un nombre es una etiqueta, no una caja.
  • Distingo tipado dinámico (no declaro tipos) de tipado fuerte (no se mezclan tipos a la fuerza).
  • Leo un traceback nuevo y digo tipo, archivo, línea y causa raíz en menos de un minuto.
  • kata-00 en verde: pytest pasa y el entorno es reproducible.
