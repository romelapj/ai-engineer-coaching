Generadores: perezosos y de memoria constante

Una función con yield no calcula ni guarda todo: pausa en cada yield y reanuda cuando le pides el siguiente. Procesa un archivo de 50 GB con memoria casi constante porque nunca lo carga entero.
  • Produce valores uno a uno, bajo demanda: pides lo que necesitas, cuando lo necesitas.
  • Es "consumir > producir" aplicado al flujo de datos.
  • Una generator expression ( ... ) es la versión de una línea: sum(x*x for x in nums) no crea la lista intermedia.

yield en acción: el concepto que cambia la escala

def lineas_validas(ruta):
    with open(ruta, encoding="utf-8") as f:
        for linea in f:                 # lee una a una
            linea = linea.strip()
            if linea and not linea.startswith("#"):
                yield linea             # entrega sin acumular

# Memoria constante aunque el archivo sea enorme:
from pathlib import Path
Path("datos.log").write_text("linea ok\n# comentario\n\notra linea\n", encoding="utf-8")  # crea el archivo de ejemplo (pathlib de N04)
total = sum(1 for _ in lineas_validas("datos.log"))

# generator expression: sin lista intermedia
suma_cuadrados = sum(n * n for n in range(1_000_000))

Un generador se consume una vez: recórrelo con for o avanza con next(). Materializar con list() anula la ventaja, hazlo solo si necesitas la colección completa.

collections: defaultdict y Counter

from collections import defaultdict, Counter

logs = [("GET", 200), ("POST", 500), ("GET", 200), ("GET", 404)]

por_metodo = defaultdict(list)
for metodo, codigo in logs:
    por_metodo[metodo].append(codigo)   # sin inicializar la lista

palabras = "el gato y el perro y el pez".split()
conteo = Counter(palabras)
print(conteo.most_common(2))   # [('el', 3), ('y', 2)]

defaultdict(list) crea la lista vacía al primer acceso; defaultdict(int) cuenta desde 0 sin inicializar. Counter es la forma idiomática de lo que en N02 hacías a mano con get/setdefault.

Módulos, imports y if __name__

Ya procesas datos de forma Pythonic. El siguiente salto no es de sintaxis sino de organización: cuando el script crece, lo partes en módulos.

Qué es un módulo

  • Un archivo .py; lo importas para reusar sus funciones y clases.
  • import modulo / from modulo import nombre / import modulo as alias.
  • Evita from x import *: contamina el namespace y oscurece de dónde viene cada nombre.

Por qué existe el guard

  • Importar un módulo ejecuta su código de nivel superior.
  • if __name__ == "__main__": separa "código que corre al ejecutar" de "código que se importa".
  • Así un archivo es script ejecutable y librería importable sin efectos colaterales.

El guard if __name__ y la estructura de un módulo

# conversor.py
def celsius_a_fahrenheit(c: float) -> float:
    return c * 9 / 5 + 32

def main() -> None:
    for c in (0, 37, 100):
        print(f"{c}C = {celsius_a_fahrenheit(c)}F")

if __name__ == "__main__":
    main()           # corre solo si ejecutas: python conversor.py
# 'from conversor import celsius_a_fahrenheit' NO dispara main()

Al importar, __name__ es el nombre del módulo; al ejecutarlo directo, es "__main__". Patrón estándar: funciones arriba, una main(), guard al final.

OOP-lite: class, __init__, self, __repr__

class CuentaBancaria:
    def __init__(self, titular: str, saldo: float = 0.0):
        self.titular = titular
        self.saldo = saldo

    def depositar(self, monto: float) -> None:
        self.saldo += monto

    def __repr__(self) -> str:
        return f"CuentaBancaria({self.titular!r}, saldo={self.saldo})"

c = CuentaBancaria("Ada", 100.0)
c.depositar(50)
print(c)        # CuentaBancaria('Ada', saldo=150.0)

self es la instancia actual; los métodos la reciben como primer parámetro. Un buen __repr__ te ahorra horas de depuración. No abuses: para un script de 30 líneas, una función basta; usa clases cuando estado y comportamiento van juntos.

dataclasses: el atajo para clases de datos

from dataclasses import dataclass, field

@dataclass
class Producto:
    nombre: str
    precio: float
    etiquetas: list[str] = field(default_factory=list)  # default seguro

    def con_iva(self, tasa: float = 0.19) -> float:
        return round(self.precio * (1 + tasa), 2)

p = Producto("Taza", 10.0, ["hogar"])
print(p)              # Producto(nombre='Taza', precio=10.0, etiquetas=['hogar'])
print(p.con_iva())    # 11.9
print(p == Producto("Taza", 10.0, ["hogar"]))  # True  (__eq__ gratis)

@dataclass genera __init__, __repr__ y __eq__ desde los campos anotados. field(default_factory=list) resuelve el default mutable de N03 limpiamente; frozen=True la hace inmutable.

pytest: por qué testear cambia cómo diseñas

# solution.py
def normalizar(nombre: str) -> str:
    return nombre.strip().lower()

# test_solution.py
from solution import normalizar

def test_normaliza_espacios_y_mayusculas():
    assert normalizar("  Ada  ") == "ada"

def test_cadena_vacia_es_borde():
    assert normalizar("   ") == ""
# pytest -q  ->  2 passed

Un test es una función test_* con un assert; pytest la descubre y reporta verde/rojo. Testear te empuja a funciones puras: lo difícil de testear suele estar mal diseñado. Cubre el camino feliz Y los bordes (vacío, malformado, límite). Verde objetivo > "se ve bien".

Cuándo función, cuándo clase, cuándo dataclass

Función

Una transformación sin estado persistente. Es el 80% de tu código.

dataclass

Un registro de datos (con quizá un par de métodos derivados). Ideal para modelar un dominio.

Clase normal

Estado mutable + comportamiento que evolucionan juntos: una cuenta, una sesión, un parser con estado.

Anti-patrón: jerarquías de herencia para 3 campos. Regla: empieza con lo más simple que funcione; sube de nivel solo cuando el dolor lo justifique. La sobre-ingeniería cuesta tu propio tiempo.
