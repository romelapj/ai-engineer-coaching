Métodos de string que usarás a diario

linea = "  2026-06-19 , Ada , admin \n"
campos = [c.strip() for c in linea.split(",")]
print(campos)                 # ['2026-06-19', 'Ada', 'admin']

partes = ["informe", "2026", "final"]
print("_".join(partes))       # 'informe_2026_final'

correo = "Ada@Ejemplo.COM"
print(correo.strip().lower()) # 'ada@ejemplo.com'
print(correo.endswith(".COM"))# True

join es método del separador, no de la lista. find devuelve -1 si no encuentra; index lanza ValueError. Los str son inmutables: estos métodos devuelven uno NUEVO, no tocan el original.

pathlib: rutas como objetos, no strings

from pathlib import Path

base = Path("datos")
base.mkdir(exist_ok=True)          # crea la carpeta datos/ si no existe
archivo = base / "usuarios.csv"      # datos/usuarios.csv
print(archivo.exists(), archivo.suffix)   # False .csv

for csv in base.glob("*.csv"):
    print(csv.name)

(base / "nota.txt").write_text("hola\n", encoding="utf-8")

El operador / compone rutas y cruza plataformas sin que te preocupes por separadores. read_text() lee todo de una; para archivos grandes, itera línea a línea con open().

with: context managers que cierran solos

from pathlib import Path

ruta = Path("eventos.log")
ruta.write_text("linea 1\n\nlinea 2\n", encoding="utf-8")  # crea el log de ejemplo
validas = 0
with ruta.open(encoding="utf-8") as f:
    for linea in f:                 # streaming: una linea a la vez
        linea = linea.strip()
        if linea:
            validas += 1
# al salir del with, el archivo ya esta cerrado
print(validas)

with garantiza el cierre aunque haya una excepción. Iterar el archivo es memoria constante, ideal para archivos grandes. Y no es solo para archivos: sirve para locks, conexiones, cualquier recurso con setup/teardown.

json: serializar y parsear

import json

texto = '{"nombre": "Ada", "roles": ["admin", "dev"], "activo": true}'
dato = json.loads(texto)
print(dato["roles"][0])         # 'admin'
print(dato["activo"] is True)   # True   (true -> True)

salida = json.dumps(dato, indent=2, ensure_ascii=False)
print(salida)                   # JSON legible, con acentos intactos

loads/dumps trabajan con texto; load/dump con archivos. Correspondencias: dict↔object, list↔array, None↔null. Un JSON malformado lanza json.JSONDecodeError (subclase de ValueError).

csv: filas y diccionarios

import csv
from io import StringIO

datos = "nombre,edad\nAda,36\nAlan,41\n"
lector = csv.DictReader(StringIO(datos))  # StringIO: envuelve el string como objeto tipo archivo; con un archivo real pasas f directamente
for fila in lector:
    print(fila["nombre"], int(fila["edad"]))   # Ada 36 / Alan 41
# DictReader usa la primera fila como claves; cada fila es un dict

csv.reader da filas como listas; DictReader da dicts usando la cabecera. Maneja comas dentro de comillas por ti: no parsees CSV con split(',') a mano. Al abrir un archivo real usa newline='' para evitar filas en blanco espurias. Para escribir: csv.writer / DictWriter con writeheader().

Errores: try/except/else/finally

Captura tipos CONCRETOS y reacciona a ESE fallo. except: pass a ciegas se traga todo, incluidos tus propios bugs.
  • try: el código que puede fallar.
  • except TipoEspecífico: cómo reaccionas a ESE fallo (ValueError, KeyError...).
  • else: corre si NO hubo excepción; separa lo arriesgado de lo seguro.
  • finally: corre siempre (limpieza), haya o no excepción.

Manejo de errores con scope correcto

def parsear_fila(linea):
    campos = linea.split(",")
    if len(campos) != 3:
        raise ValueError(f"esperaba 3 campos, vi {len(campos)}")
    nombre, edad, rol = campos
    return {"nombre": nombre, "edad": int(edad), "rol": rol}

descartadas = 0
for linea in ["Ada,36,admin", "corrupta", "Bea,xx,dev"]:
    try:
        fila = parsear_fila(linea)
    except ValueError:             # tipo concreto, scope minimo
        descartadas += 1           # descarta + cuenta, no revienta
    else:
        print(fila)
print("descartadas:", descartadas) # descartadas: 2

El try envuelve SOLO la línea que puede fallar, no medio programa. raise lanza una excepción; raise NuevaError(...) from e preserva la causa original.

La jerarquía de excepciones

Cómo se ordena

  • Todas heredan de BaseException; las que capturas heredan de Exception.
  • ValueError, KeyError, IndexError, TypeError, FileNotFoundError son subclases concretas.
  • Capturar una superclase atrapa a sus hijas: except Exception atrapa casi todo, por eso es peligroso.

Tu regla práctica

  • Puedes definir las tuyas: class DatosInvalidos(Exception): pass (la sintaxis class la vemos en la próxima sesión, N05).
  • Captura lo más específico que puedas reaccionar.
  • Deja subir lo que no sabes manejar: un fallo visible vence a uno silenciado.

EAFP vs LBYL

EAFP (Easier to Ask Forgiveness than Permission): intenta el camino feliz y captura el caso raro específico.
  • LBYL (Look Before You Leap): comprueba condiciones ANTES de actuar, como if clave in dict: ....
  • EAFP: intenta y captura el fallo, como try: d[k] / except KeyError.
  • Python favorece EAFP: más rápido (sin doble lookup), evita race conditions y suele leerse mejor.
  • No es absoluto: para una validación simple, un if claro gana; para operaciones que normalmente funcionan, EAFP.
  • La clave: capturar el tipo concreto, no envolver todo en un try gigante por superstición.

EAFP en acción + leer tracebacks, otra vez

def a_entero(valor, default=0):
    try:
        return int(valor)          # EAFP: intenta
    except (ValueError, TypeError):
        return default             # captura SOLO lo que esperas

print(a_entero("42"))   # 42
print(a_entero("abc"))  # 0
print(a_entero(None))   # 0

# Si capturas de mas (except Exception), ocultas bugs reales tuyos.

Cuando un except te sorprende, el traceback te dice exactamente qué subió. Repite el hábito de N00: leer de abajo a arriba, ir a la línea, reproducir.
