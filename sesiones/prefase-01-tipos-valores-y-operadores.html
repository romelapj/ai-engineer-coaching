Los tipos que vas a usar todo el día

Tipo Qué es Ejemplos
int Enteros de precisión arbitraria (no hay overflow) 42, -7, 10_000
float Coma flotante IEEE 754 3.14, 1e-3, float('inf')
str Texto Unicode inmutable 'hola', 'linea\n'
bool Subtipo de int: True==1, False==0 True, False
None Ausencia de valor (singleton) None

Cinco tipos básicos. bool es literalmente un int disfrazado, y eso será útil más adelante.

Conversión SIEMPRE explícita

# El dato que nos acompaña hoy: una linea de un CSV de precios
fila = "café,1990,"              # nombre, precio (texto), stock (vacio)
nombre, precio_str, stock_str = fila.split(",")

# print(precio_str + 100)       # TypeError: no se mezcla str con int
precio = int(precio_str)          # conversion explicita: '1990' -> 1990
etiqueta = "Total: $" + str(precio)  # concatenar pide str() explicito
print(nombre, etiqueta)          # café Total: $1990

int(), float(), str(), bool() son los conversores. Ojo: int('3.0') lanza ValueError (no es un entero literal), pero int(float('3.0')) funciona — el camino importa.

Dos trampas numéricas que debes conocer

print(0.1 + 0.2)                     # 0.30000000000000004
import math
print(math.isclose(0.1 + 0.2, 0.3)) # True

print(7 / 2, 7 // 2, 7 % 2)         # 3.5 3 1

activos = [True, False, True, True]
print(sum(activos))                 # 3   (bool suma como int)

float no es exacto: nunca compares floats con == a secas — usa math.isclose. Para dinero (como el precio de la fila) usa enteros en centavos o decimal.Decimal. Recuerda: / siempre da float, // es división entera, % es el resto.

f-strings: formato que se lee

nombre, precio = "café", 1990
print(f"{nombre:<10}|{precio:>10.2f}")  # café      |   1990.00

tasa = 0.3082
print(f"Error: {tasa:.1%}")             # Error: 30.8%

total = 1500000
print(f"{total:,}")                      # 1,500,000

x = 42
print(f"{x=}")                          # x=42   (debug instantaneo)

Mini-lenguaje tras : — .2f dos decimales, >8 ancho 8 a la derecha, , separador de miles, .1% porcentaje, !r usa repr(). Y f'{valor=}' imprime nombre y valor: oro puro para depurar.

Truthiness: "falso" sin ser False

Qué pasa en un if

  • En un if o en and/or, Python evalúa la "verdad" del objeto, no solo True/False.
  • Falsy: None, False, 0, 0.0, '', [], {}, set() vacío.
  • Truthy: todo lo demás — cualquier número no cero, cualquier colección no vacía.

Por qué importa

  • if items: es idiomático para "si la lista no está vacía", mejor que if len(items) > 0.
  • and/or devuelven un operando, no un bool.
  • nombre or "anonimo" da un default elegante en una línea.

Truthiness en la práctica

def resumen(nombres):
    if not nombres:                 # None o lista vacia
        return "sin datos"
    return ", ".join(nombres)

print(resumen([]))                  # 'sin datos'
print(resumen(["Ana", "Beto"]))     # 'Ana, Beto'

stock_str = ""                     # el mismo campo vacio de la fila de café
stock = stock_str or "sin stock"   # '' es falsy -> usa el default
print(stock)                        # 'sin stock'

Cuidado con la trampa: 0 es falsy, así que stock or 10 convierte un 0 legítimo (un stock agotado) en 10. Cuando el cero es un valor válido, usa stock if stock is not None else 10.

La gran línea: mutable vs inmutable

"Modificar" un str con s.upper() en realidad crea un str nuevo; el original jamás cambió. Esa distinción decide si pasar un objeto a una función puede alterarlo desde fuera.

Inmutables

  • int, float, str, bool, tuple, frozenset.
  • Una vez creados, no cambian. Pasarlos a una función es seguro.

Mutables

  • list, dict, set.
  • Se modifican en su sitio (.append, [k]=v, .add). Una función puede mutarlos.

Es la causa #1 de bugs sutiles para quien viene de lenguajes con otra semántica de copia.

Mutabilidad: el bug del aliasing

a = [1, 2, 3]
b = a                  # b NO es una copia: misma lista
b.append(4)
print(a)               # [1, 2, 3, 4]  <- a tambien cambio

c = a[:]               # ahora si, una copia superficial
c.append(99)
print(a)               # [1, 2, 3, 4]  <- a intacta

s = "hola"
t = s.upper()          # crea un str nuevo
print(s, t)            # hola HOLA   <- s NO cambio

Reasignar (s = s + 'x') crea un objeto nuevo; mutar (lista.append('x')) toca el mismo. Dos nombres pueden apuntar a la MISMA lista: el clásico aliasing inesperado cuando crees que copiaste pero solo etiquetaste.

is vs == : identidad vs igualdad

a = [1, 2]
b = [1, 2]
print(a == b)     # True  (mismo valor)
print(a is b)     # False (objetos distintos)

descuento = None  # la fila de café no traia columna de descuento
print(descuento is None)  # True  <- idiomatico

n = 1000
m = 1000
print(n == m)     # True  (siempre, por valor)
# print(n is m)   # depende de la cache: NO te apoyes en esto

== compara VALOR (¿representan lo mismo?); is compara IDENTIDAD (¿son el mismo objeto?). Casi siempre quieres ==; usa is solo con singletons: None, True, False. Enteros chicos y strings cortos a veces comparten objeto por caché, pero NUNCA dependas de eso.

Asignación múltiple y desempaquetado

x, y = 10, 20
x, y = y, x                 # swap, sin variable temporal
print(x, y)                 # 20 10

punto = (4, 7)
col, fila = punto           # nombres con sentido > punto[0], punto[1]

primero, *resto = [1, 2, 3, 4]
print(primero, resto)       # 1 [2, 3, 4]

anio, mes, dia = "2026-06-19".split("-")   # desempaquetado tras split

En a, b = b, a Python construye primero la tupla de la derecha, luego la desempaqueta: por eso el swap funciona sin temporal. El * captura "el resto" en una lista.
